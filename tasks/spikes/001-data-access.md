# Spike 001 — 데이터 접근성 1차 판정

상태: **진행 중 — 실제 키와 11개 공원 단일 시점 검증 완료**
조사일: 2026-08-12

## 질문

1. 11개 한강공원의 도착 시점 혼잡·날씨·행사 정보를 무료로 얻을 수 있는가?
2. 참여자×11개 공원의 대중교통 시간을 MVP 무료 범위에서 계산할 수 있는가?
3. 정확한 만남 지점을 공식 데이터만으로 만들 수 있는가?

## 결론

### 1. 상황 데이터 — 조건부 가능

서울시 실시간 도시데이터가 11개 한강공원, 현재 혼잡, 향후 12시간 인구 예측, 환경과 문화행사를 포괄한다. 무료이며 출처표시형 라이선스로 안내된다.

단, 12시간 밖 약속의 혼잡 예측은 제공하지 못한다. 과거 실시간 값도 제공되지 않아 서비스가 자체 과거 패턴을 즉시 학습할 수 없다. 따라서 며칠 뒤 약속에 “도착 시점 혼잡도”를 약속하는 현재 MVP 문구는 데이터 범위와 충돌한다.

### 2. 대중교통 경로 — 작은 파일럿은 가능, 성장 시 비용 발생

카카오맵 REST API가 기능과 무료 한도 측면에서 가장 유력하다. 1,000회/일 무료지만 3명 약속 하나가 33회이므로 전체 11개 공원을 매번 계산하면 하루 약 30개 약속이 상한이다.

무료 한도는 개발자 계정의 첫 번째 카카오맵 활성화 앱에만 적용된다. 현재 문서의 추가 사용 단가는 10원/경로 호출이다. 비용 설정은 사용자 승인 전 활성화하지 않는다.

카카오 요청에는 미래 출발/도착 시각이 없으므로 결과를 “해당 시각 시간표 기반”이라고 표현할 수 없다. 현재 목표는 정적/현재 기준 예상 이동시간으로 설명해야 한다.

### 3. 정확한 만남 지점 — 수동 카탈로그 필요

공식 한강 안내 파일은 콘텐츠 인덱스이고 시설 좌표 목록이 아니다. 공원별 대표 지점을 자동으로 정할 수 있는 공식 데이터는 찾지 못했다. 지도 POI와 미래한강본부 페이지를 교차 확인해 11개 공원 카탈로그를 직접 관리해야 한다.

## 공급자 우선순위

1. **서울시 실시간 도시데이터:** 혼잡·날씨·행사
2. **카카오맵 REST API:** 장소 검색·대중교통 경로·지도 연결
3. **TMAP:** 하루 10회 무료 표본으로 이동시간 교차 검증
4. **ODsay:** 반복 계산 약관을 서면 확인하기 전 보류

## 제품에 필요한 결정

### 승인됨: 2단계 추천

- **12시간보다 먼 약속:** 이동 공평성·정적 시설을 바탕으로 “임시 추천”을 제공하고 혼잡은 아직 예측 범위 밖이라고 표시
- **12시간 이내:** 도착 시각 혼잡과 최신 날씨·행사를 반영해 추천 갱신
- 장소가 바뀌면 방장에게 차이와 이유를 보여주고 승인받음

이 방식은 데이터가 없는 시점에 혼잡을 꾸며내지 않으면서 미리 약속을 만들 수 있게 한다.

사용자 승인일: 2026-08-12

## 다음 실험

### 키 상태

- 서울 열린데이터광장 일반 인증키: 발급 및 실제 호출 확인
- 카카오 Developers 앱의 REST API 키: 발급 및 실제 호출 확인
- 선택 TMAP/SK open API 앱 키: 미발급

키는 저장소에 넣지 않고 로컬 환경변수로만 주입한다. 키 발급은 외부 계정 생성/약관 동의를 수반하므로 사용자가 직접 발급하거나 명시적으로 위임해야 한다.

### 1차 실제 접근 결과 — 2026-08-12

- 서울시 실시간 도시데이터: 여의도한강공원 표본 성공
  - 혼잡 단계, 인구 관측 시각, 13개 예측 항목, 날씨 관측 시각 확인
  - 행사 항목은 표본 시점에 0개
- 카카오맵 REST API: 장소 검색과 대중교통 경로 표본 성공
  - 홍대입구역·여의나루역 검색 성공
  - 경로 15개, 최단 약 19분 반환
- 키, 응답 원문, 좌표는 저장하거나 출력하지 않음
- 아직 시간대별 경로 품질, 무료 쿼터 배지·차감 상태는 검증하지 않음

### 11개 공원 단일 시점 결과 — 2026-08-12

- 11곳 모두 요청 성공 및 필수 혼잡·예측·날씨 필드 확인
- 모든 공원에서 13개의 1시간 간격 인구 예측과 24개의 날씨 예보 확인
- 모든 공원에서 주차장 2~9개, 실시간 주차 제공 항목 최소 1개 확인
- 문화행사는 망원·이촌 각 1개, 나머지 9곳은 0개
- 인구 관측값은 호출 시점보다 약 32분 전, 날씨는 약 7분 전
- 후속 호출에서 인구 관측 시각은 5분 진행했지만 호출 시점과의 차이는 약 28분으로 유지
- 인구 대체 데이터 사용 여부는 11곳 모두 `N`
- 순차 호출 응답시간 중앙값 약 82ms, 최대 약 161ms
- 한 번의 심야 표본이므로 시간대별 안정성이나 갱신 지연의 일반적인 수준으로 해석하지 않음

재검증은 로컬 `.env`에 키를 주입한 뒤 다음 명령으로 수행한다.

```bash
node --test scripts/validate-data-access.test.mjs
node scripts/validate-data-access.mjs
node scripts/validate-data-access.mjs --provider=seoul
node scripts/validate-data-access.mjs --provider=seoul-all
node scripts/validate-data-access.mjs --provider=kakao
```

검증 스크립트는 키와 원본 응답을 출력하거나 파일로 저장하지 않는다.

### 표본 매트릭스

- 출발지: 홍대입구역, 강남역, 노원역
- 공원 지점: 서부·중부·동부 각 1곳의 검증 후보
- 시각: 평일 낮, 평일 퇴근, 주말 저녁, 막차 근처
- 상태: 정상, 없는 경로, 모호한 장소, 오래된 상황 데이터, 일부 공원 누락

### 통과 기준

- 동일 입력 반복 호출의 이동시간 변동과 응답시간 기록
- 카카오↔TMAP 이동시간 차이의 분포 기록
- 공원별 마지막 도보 구간이 실제 접근 경로와 일치
- 서울시 11개 공원 응답에서 관측/예측 시각과 누락 필드 확인
- 비밀키가 로그·fixture·Git 변경에 남지 않음

## 이번 스파이크에서 아직 하지 않은 것

- 유료 API 활성화
- 실제 API 응답을 fixture로 저장
- 추천 가중치 결정
- 프론트엔드 또는 Express 코드 생성

따라서 11개 공원의 단일 시점 접근 가능성은 확인했지만 여러 시간대의 안정성과 경로 품질은 아직 통과시키지 않았다.
