# 리스크 우선 로드맵

이 로드맵은 화면 완성 순서가 아니라 제품을 무효화할 수 있는 위험을 먼저 제거하는 순서다. 각 단계는 증거와 사용자 검수 지점이 있어야 다음 단계로 넘어간다.

## 단계 0. 하네스와 결정 기록 — 완료

**목표:** 구현 범위, 작업 원칙, 검수 기준을 고정한다.

**산출물:**

- `PRODUCT.md`
- `AGENTS.md`
- `docs/ACCEPTANCE.md`
- `docs/ARCHITECTURE.md`
- `tasks/ROADMAP.md`

**종료 기준:** 문서 간 MVP 입력·출력·비범위가 일치하고, 기술 선택이 확정/가설로 구분된다.

**사용자 검수:** 핵심 타깃, 첫 사용 사례, 미결정 선택을 승인한다.

## 단계 1. 데이터 접근성 스파이크 — 1차 완료

**현재 상태(2026-08-12):** 공식 문서 조사, 서울시 11개 한강공원 단일 시점 호출, 11개 임시 만남 지점, 세 출발지×세 공원 카카오 대중교통 경로 표본을 완료했다. 다음 단계 진행을 막는 접근성 위험은 발견되지 않았다. 여러 시간대의 안정성·마지막 도보 품질·만남 지점 현장 식별성은 실데이터 통합 전까지 후속 검증한다.

### 1A. 데이터 원장

서울 실시간 도시데이터, 미래한강본부, 기상/대기/일몰, 행사·통제 후보를 실제 공식 문서와 표본 응답으로 조사한다.

각 소스에 대해 다음을 기록한다.

- 제공 범위와 한강공원 식별 방식
- 관측값/예측값 구분
- 갱신주기와 시간대
- 인증, 호출 한도, 비용
- 캐시·재배포·출처 표기 약관
- 누락/장애 응답 형태
- MVP 필수 여부와 대체 가능성

### 1B. 경로 API 비교

대중교통만 대상으로 최소 3명 × 여러 출발지 × 후보 만남 지점 표본을 계산한다. 지원 지역, 도착 시각 경로, 비용, 한도, 약관, 좌표/역 검색 품질을 비교한다.

### 1C. 공원·만남 지점 카탈로그 검증

11개 공원에 대해 공원 중심점이 아니라 현장에서 식별 가능한 후보 지점을 수집한다. 공식 출처와 지도 서비스 표기를 교차 확인하고, 접근역/출입구와 연결한다.

**산출물:** 데이터 원장, 익명 fixture, 공급자 비교표, 호출 실험, 위험 목록.

**중단 조건:** 합법적이고 비용 가능한 대중교통 경로 또는 도착 시점 상황 데이터를 확보할 수 없고 현실적인 대체안도 없다면 UI 구현 전에 제품 약속을 축소하거나 변경한다.

**사용자 검수:** 유료 API가 필요할 때의 비용 승인과 데이터 부족 시 제품 문구 변경. 자동차는 MVP에서 제외한다.

## 단계 2. 추천 가능성 스파이크 — 방향 승인·대표 실경로 검증 완료

코드 UI 없이 고정 fixture를 입력해 11개 후보를 평가하는 실행 가능한 도메인 프로토타입을 만든다.

**현재 상태(2026-08-12):** 순수 TypeScript 엔진과 9개 고정 사례로 B1~B4, D1, E1~E4를 재현했다. 사용자가 균형 중심 방향을 승인했으며, 대표 출발지 5조합×11개 공원의 실제 카카오 경로 165개도 오류 없이 평가했다. 실제 사용자 약속 5~10개의 사람 판단 비교와 정확한 가중치 검수가 남았다.

검증 항목:

- 평균 이동시간, 최장 이동시간, 편차 중 공평성 정의
- 절대 제외 조건과 감점 조건
- 도착 예상 시각 계산 방식
- 혼잡·날씨·시설·행사/통제의 정규화
- 데이터 신뢰도와 누락 처리
- 1순위/대안 및 동률 처리
- 구조화된 비교 근거

실제 약속 5~10개를 사람이 수동 평가하고 프로토타입 순위와 비교한다. 가중치를 결과에 맞춰 무작정 조정하지 말고, 변경 이유와 실패 사례를 남긴다.

**산출물:** 버전이 있는 결정 규칙, 테스트 벡터, 설명 예시, 오판 사례 목록.

**종료 기준:** `docs/ACCEPTANCE.md`의 B와 E 시나리오를 고정 입력으로 재현한다.

**사용자 검수:** 공평성 정의, 추천/대안 표현, 납득 가능한 설명 수준.

## 단계 3. 개인정보·공유 링크 위협 모델 — 완료

구현 전에 다음을 결정한다.

**현재 상태(2026-08-12):** 최소 수집·삭제 수명주기, 초대/참가자/방장 권한 분리, 256비트 링크 토큰, 로그 허용목록과 개인정보 안내 초안을 작성했다. 사용자가 역·공개 장소만 입력, 초안 7일/약속 후 24시간/백업 30일 삭제, 로그인 없는 권한과 복구 제한을 모두 승인했다.

- 출발지 정밀도와 원문 보관 필요성
- 게스트 링크의 엔트로피, 만료, 수정/조회 권한
- 방장 인증과 약속 삭제
- 로그·분석 이벤트 허용 필드
- 보관 기간과 자동 삭제
- 유출/남용 시나리오와 대응

**산출물:** 간단한 위협 모델, 데이터 수명주기, 권한 표, 개인정보 안내 초안.

**종료 기준:** 정확한 집 주소를 기본 수집하지 않고도 핵심 추천이 가능하거나, 추가 정밀도의 명시적 이유와 보호책이 승인된다.

**사용자 검수:** 보관 기간, 게스트가 볼 수 있는 정보, 방장 권한.

## 단계 4. 확정 스택 하네스와 세로형 프로토타입

TypeScript + React 클라이언트와 TypeScript + Node.js/Express API를 단일 저장소 하네스로 구성한다. 공유 링크 참여 폼과 결과 카드 한 조각만 구현해 경계와 자동화를 검증한다.

비교 기준:

- iOS Safari, Android Chrome, 데스크톱 브라우저 실제 실행
- 설치 없는 공유 링크 진입과 링크 미리보기
- 접근성 및 입력 사용성
- 지도 앱/지도 웹 연결과 폴백
- 자동 테스트와 CI 안정성
- 빌드/배포 자동화 복잡도
- 클라이언트 전송 크기와 저사양 모바일 초기 로딩

**산출물:** ADR, 최소 저장소 골격, 자동 포맷/정적 분석/테스트/비밀 스캔.

**사용자 검수:** 모바일·데스크톱 브라우저의 실제 체감. 빌드 도구나 배포 서비스가 비용·운영에 중요한 영향을 줄 때만 별도 선택을 요청한다.

## 단계 5. 첫 수직 슬라이스

fake 데이터로 다음 여정을 끝까지 연결한다.

1. 방장 약속 생성
2. 게스트 2명 이상 링크 참여
3. 추천 계산
4. 추천 1곳/대안 1곳과 근거 표시
5. 정확한 만남 지점 및 지도 연결
6. 12시간 밖 임시 추천과 12시간 이내 최신 추천 갱신
7. 추천 변경 시 방장 승인

이 단계에서는 실데이터 통합보다 상태·권한·추천 계약을 안정화한다.

**종료 기준:** 자동 E2E와 `ACCEPTANCE` A, B, C, D1~D3의 핵심 시나리오 통과.

**사용자 검수:** 코드 없이 실제 모바일 브라우저에서 핵심 여정을 수행한다.

## 단계 6. 실데이터 통합과 장애 내성

스파이크에서 승인된 공급자를 어댑터 단위로 연결한다.

순서:

1. 공원·만남 지점 카탈로그
2. 경로시간
3. 혼잡 관측/예측
4. 날씨와 피크닉 위험
5. 행사·통제

자동차·주차는 이 통합 단계에 포함하지 않고 MVP 이후 별도 데이터 검증 대상으로 둔다.

각 통합마다 계약 fixture, 최신성 정책, 시간 초과, 429, 빈 응답, 일부 실패를 검증한다.

**종료 기준:** `ACCEPTANCE` D와 E 통과, API 비용/한도 대시보드 또는 알림 준비.

## 단계 7. 비공개 현장 파일럿

소수 실제 약속에서 다음을 관찰한다.

- 링크 참여 완료율과 이탈 지점
- 추천 확정까지 걸린 시간
- 지도 도착 지점의 현장 식별 가능성
- 예상 이동시간/혼잡과 체감 차이
- 추천 이유 이해도와 1순위 수용 여부
- 삭제·만료 동작

문제는 UI, 데이터, 추천 규칙, 제품 약속 중 어느 계층인지 구분해 수정한다.

**종료 기준:** 사전에 확정한 품질 문턱 충족, 치명적 개인정보/권한 문제 없음, 핵심 실패 사례 회귀 테스트 추가.

**사용자 검수:** 파일럿 결과를 바탕으로 공개 MVP 여부 결정.

## 단계 8. 공개 MVP와 관찰

- 최소 운영 지표와 외부 API 상태 감시
- 오류 예산 및 비용 한도 알림
- 사용자 피드백과 추천 이의 제기 수집
- 데이터 출처·갱신 시각·개인정보 안내 공개
- 롤백 가능한 배포 절차 확인

후속 기능은 핵심 지표와 실패 사례가 확보된 뒤 우선순위를 정한다. 러닝·반려견·아이 동반·한강 밖 확장은 별도 제품 검증을 거친다.

## 확정된 초기 결정

1. 약속 시간은 모두의 도착 완료 시각이다.
2. 자동차는 MVP에서 제외하고 대중교통만 지원한다.
3. 출발지는 역·공개 장소 검색만 지원하며 현재 위치·정확한 주소는 MVP에서 받지 않는다.
4. TypeScript + React 클라이언트와 TypeScript + Node.js/Express API를 사용한다.
5. 외부 API는 무료 범위에서 우선 검증하고, 비용이 발생하기 전에 사용자 승인을 요청한다.
6. 12시간 밖 약속은 임시 추천을 제공하고, 12시간 이내에 혼잡을 반영해 갱신한다. 장소 변경은 방장 승인 후 적용한다.
7. 미완성 약속은 7일, 확정 약속은 약속 후 24시간, 백업은 최대 30일 보관한다.
8. 초대·참가자·방장 권한을 분리하고 로그인 없는 MVP에서는 기기 간 권한 복구를 제공하지 않는다.

## 다음 검수 전까지 위임된 선택

- 무료 데이터/API 후보 조사와 표본 호출
- 테스트용 fixture와 데이터 원장 형식
- 되돌릴 수 있는 로컬 개발·검증 도구

데이터베이스·배포 서비스, 유료 API, 개인정보 보관 정책, 추천 가중치는 별도 검수 없이 확정하지 않는다.
