# 클릭 가능한 핵심 여정

## 목적

실제 카카오 대중교통 경로와 서울시 도착 혼잡 예측을 사용해 다음 제품 계약이 하나의 웹 여정으로 연결되는지 검증한다. API 키가 없는 개발·자동 테스트 환경에서는 동일 계약의 fixture가 동작한다.

1. 방장이 약속을 만든다.
2. 설치와 로그인 없이 공유 링크로 친구가 참여한다.
3. 친구 2명이 별칭을 입력하고 카카오맵 검색 결과에서 출발 장소를 선택한다.
4. 같은 계산 결과에서 추천 1곳, 역할이 다른 대안 2곳, 실제 도착 시각 혼잡 예측, 만남 지점과 공원 특징을 표시한다.
5. 방장이 참여 현황과 같은 추천 결과를 확인하고 후보 중 장소를 확정한다.

## 실행과 검수

Node.js 22.12 이상에서 의존성을 설치한 뒤 두 터미널을 사용한다.

```bash
npm install
npm run dev:api
```

```bash
npm run dev:web
```

브라우저에서 `http://127.0.0.1:5173`을 열고 다음을 확인한다.

1. 약속 시간을 정하고 **피크닉 약속 만들기**를 누른다.
2. 방장 화면의 **친구 화면 열기**를 새 탭에서 연다.
3. 예를 들어 `민지`가 `인천대학교 송도캠퍼스`를 검색하고 주소·카테고리를 확인해 정확한 결과를 선택한 뒤 제출한다.
4. 같은 화면에서 **다른 친구 입력도 테스트하기** 또는 다시 표시된 입력 폼을 사용해 `준호 · 아주대학교`를 제출한다.
5. `LIVE ROUTE · LIVE CROWD`, 카카오 경로 조회 시각, 오늘의 추천·이동 균형 대안·다른 즐길거리 대안, 서울시 도착 혼잡 예측과 기준 시각, 정확한 만남 지점, 공원별 특징과 제한이 표시되는지 확인한다.
6. 방장 탭에서 **새로고침**을 눌러 참여자 2명과 동일한 결과가 표시되는지 확인한다.
7. 후보 한 곳의 **이 장소로 확정** 버튼을 누르고 새로고침 뒤에도 확정 표시가 유지되는지 확인한다.

실제 API 결과는 호출 시점에 달라질 수 있어 특정 공원을 통과 기준으로 고정하지 않는다. 1순위는 이동 공평성과 도착 혼잡 계산 결과, 첫 대안은 차순위, 두 번째 대안은 상위권에서 다른 대표 경험을 제공하는 후보로 구성한다. 고정 fixture는 추천 규칙의 회귀 테스트에만 사용한다.

## 현재 보호 경계

- 초대·방장 토큰은 256비트 난수이며 서버 메모리에는 SHA-256 해시만 저장한다.
- 권한 토큰은 `HttpOnly`, `SameSite=Strict` 쿠키로 전달한다.
- 방장 결과에는 친구 별칭과 이동시간만 표시하고 출발 장소 ID·이름·주소·좌표는 반환하지 않는다.
- 클라이언트가 추천을 재계산하지 않고 서버의 구조화된 결과만 표현한다.

## 의도적으로 남긴 제한

- 서버를 재시작하면 약속이 사라지는 메모리 저장소다.
- 출발지는 카카오에 등록된 키워드 장소를 검색한다. 정확한 주소 직접 입력과 현재 위치 권한은 제공하지 않는다.
- 검색 결과의 공개 주소·카테고리는 사용자가 동명 장소를 구분하는 동안만 표시하고, 약속에는 카카오 장소 ID와 이름만 저장한다. 좌표는 서버 메모리에서 경로 계산에만 사용한다.
- 카카오 이동시간은 조회 시점 기준이며 미래 약속 시각의 정확한 시간표가 아니다.
- 경로 성공은 2시간, 일시 실패는 30초 메모리 캐시하며 프로세스별 일 900회에서 무료 쿼터 보호를 위해 중단한다. 서버 재시작을 넘는 사용량 계수는 아직 없다.
- 날씨·행사·통제와 지도 연결은 아직 없다.
- 추천 개정과 방장 승인, 링크 만료·자동 삭제는 아직 동작하지 않는다.
- 같은 브라우저에서 두 친구를 연속 제출하는 기능은 검수 편의를 위한 임시 동작이다.
- 현재 화면은 기능 검수용이며 최종 디자인 시스템을 적용하지 않았다.
