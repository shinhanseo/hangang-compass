# 데이터 원장

조사 기준일: 2026-08-12 (Asia/Seoul)

이 문서는 공식 문서에서 확인한 데이터/API 후보와 아직 검증하지 못한 항목을 구분한다. 실제 키를 발급받아 표본 응답을 저장하기 전까지 필드 품질과 응답 안정성은 확정하지 않는다.

## 상태 표기

- **채택 후보:** MVP 요구를 상당 부분 충족하며 실제 응답 검증이 남음
- **보조 후보:** 일부 요구 또는 교차 검증에 사용 가능
- **보류:** 약관·호출량·품질 위험이 해소되기 전에는 핵심 경로에 사용하지 않음
- **부적합:** 현재 형태로 MVP 요구를 충족하지 못함

## 요약 판정

| 영역 | 1순위 후보 | 판정 | 핵심 제약 |
|---|---|---|---|
| 혼잡 관측·12시간 예측 | 서울시 실시간 도시데이터 | 채택 후보 | 한 번에 한 장소, 인증키 필요, 예측은 12시간, 과거 API 없음 |
| 날씨·대기·일출/일몰 | 서울시 실시간 도시데이터 내 환경 정보 | 채택 후보 | 데이터별 갱신주기 상이, 실제 응답 최신성 검증 필요 |
| 행사 | 서울시 실시간 도시데이터 문화행사 | 보조 후보 | 1일 갱신, 공원 행사 누락 여부 검증 필요 |

| 정확한 만남 지점 | 수동 검증 카탈로그 + 지도 POI | 보류 | 11개 임시 후보 구성 완료, 현장 식별성 미검증 |

### 확인된 범위

- 11개 한강공원 모두 주요 장소 목록에 포함된다.
  - 강서, 광나루, 난지, 여의도, 잠원, 양화, 뚝섬, 망원, 반포, 이촌, 잠실
- 한 장소 단위로 인구 혼잡, 교통, 날씨/환경, 문화행사 등을 통합 조회한다.
- API는 한 번에 한 장소만 호출한다.
- 실시간 인구는 5분, 날씨/환경은 10분, 문화행사는 1일 주기로 안내된다. 세부 원천별 주기는 다를 수 있다.
- 향후 12시간 인구 예측을 제공한다. 과거 12시간을 입력으로 사용하며 축제 등에 따른 급격한 변화가 일부 반영되지 않을 수 있고 실제 인구와 다를 수 있다고 명시한다.
- 실시간 데이터의 과거값은 별도 제공하지 않는다.
- 공공누리 제1유형으로 출처표시 조건 아래 상업적 이용과 변경이 가능하다고 데이터셋에 표시된다.
- 무료 제공이지만 정식 인증키 발급이 필요하다. 샘플 키는 특정 장소와 소량 조회로 제한된다.
- 공식 호출 URL은 현재 HTTP 8088로 안내된다. 2026-08-12 sample 요청으로 HTTPS 8088과 표준 443을 확인했으나 각각 TLS 오류와 연결 시간 초과가 발생했다. 인증키가 전송 구간에서 암호화되지 않는 위험을 운영 전 해결하거나 수용 여부를 검토해야 한다.
- 2026-07-22에는 121곳 중 71곳의 인구가 원천 집계 누락으로 과소 추정된 품질 오류가 공식 공지됐다. HTTP 성공과 최신 시각만으로 값의 정확성을 완전히 보장할 수 없다.

### MVP 사용 제안

- 11개 공원의 현재 혼잡과 도착 시각 혼잡 예측의 1순위 소스로 사용한다.
- 한 번에 한 장소만 조회하므로 11개 응답을 짧은 TTL로 서버 캐시하고 약속마다 재호출하지 않는다.
- 각 필드에 `observedAt`, `forecastFor`, `fetchedAt`, `freshness`, `source`를 보존한다.
- 12시간 밖 약속에는 혼잡 예측을 만들지 않는다. 과거 데이터가 없으므로 임의의 자체 예측도 하지 않는다.
- 응답의 행사·사고통제가 실제 한강공원 내부 행사/폐쇄를 얼마나 포괄하는지 별도 표본 검증한다.

### 미검증

- 여러 시간대에 11개 공원을 반복 호출했을 때의 오류율과 필드 누락
- 인증키별 정확한 호출량 정책과 운영 서비스 등록 요건
- 날짜 경계에서 예측 배열의 시각과 개수 변화
- 공원 내부 행사·침수·공사 통제의 포함 범위

### 실제 키 표본 검증 — 2026-08-12

- `여의도한강공원` 통합 도시데이터 요청이 HTTP 200으로 응답했다.
- 요청 장소명, 혼잡 단계, 인구 관측 시각, 날씨 관측 시각이 존재했다.
- 인구 예측 항목 13개가 반환됐다. 이것이 항상 같은 개수인지와 각 항목의 시간 간격은 11개 공원 표본에서 추가 검증한다.
- 행사 항목은 0개였다. 이는 검증 시점의 표본 결과이며 행사 데이터 제공 범위가 충분하다는 의미가 아니다.
- 응답시간은 단일 로컬 표본에서 약 0.2초였다. 운영 성능 보장값으로 사용하지 않는다.
- 정상 데이터 응답에는 `CODE` 필드가 없었다. 성공 여부는 HTTP 상태와 필수 데이터 필드로 판정하고, 오류 응답에 `CODE`가 존재하면 오류 코드도 함께 판정한다.

### 11개 공원 단일 시점 검증 — 2026-08-12

- 11개 공원 모두 HTTP 200과 요청한 장소명·장소코드를 반환했다.
- 모든 공원에 혼잡 단계, 인구 관측 시각, 인구 예측, 날씨 관측 시각이 존재했다.
- 모든 공원의 예측은 검증 시점에 13개였고 1시간 간격이었다. 첫 예측부터 마지막 예측까지의 차이는 11시간이므로 13개 지점을 “13시간 예측”으로 표현하지 않는다.
- 모든 공원에 24개의 날씨 예보 항목이 있었다.
- 모든 공원에 주차장이 2~9개 있었고, 실시간 주차 제공 항목도 최소 1개 이상 있었다. 주차장 전체 개수와 실시간 제공 개수를 구분한다.
- 문화행사는 망원·이촌에서 각 1개, 나머지 9개 공원에서 0개였다. 0개를 데이터 장애와 구분해야 한다.
- 인구 관측 시각은 11곳 모두 호출 시점보다 약 32분 전이었고, 날씨는 약 7분 전이었다. 안내 갱신주기와 실제 최신성이 항상 같다고 가정하지 않고 원본 관측 시각으로 상태를 판정해야 한다.
- 후속 단일 호출에서는 인구 관측 시각이 5분 진행했지만 호출 시점과의 차이는 약 28분이었다. 갱신 간격과 데이터 지연을 별도 개념으로 다뤄야 한다.
- 인구 데이터의 `REPLACE_YN`은 11곳 모두 `N`이었다.
- 순차 호출 응답시간은 중앙값 약 82ms, 최대 약 161ms였다. 단일 로컬 실행 결과이므로 운영 성능 보장값으로 사용하지 않는다.

### 제품 영향

- 화면에는 “실시간” 문구만 표시하지 않고 실제 관측 시각 또는 경과 시간을 함께 표시한다.
- 추천 계산은 `fetchedAt`이 아니라 `PPLTN_TIME`과 `WEATHER_TIME`을 기준으로 최신성을 판단한다.
- 최신성 임계값은 반복 관측 후 확정한다. 현재 1회 표본만으로 32분 데이터를 정상 또는 장애로 단정하지 않는다.
- 행사 0개와 행사 데이터 누락을 구분할 수 있는 내부 상태가 필요하다.
- 주차는 전체 주차장 수와 실시간 잔여면 정보를 제공하는 주차장 수를 분리한다.

### 내부 정규화 스파이크 — 2026-08-12 14:22 KST

- 서울시 XML을 공급자 형식과 분리된 `CrowdSnapshot`으로 변환하는 서버 어댑터를 추가했다.
- 현재 혼잡에는 공원 ID·장소명·장소코드·혼잡 단계·관측 시각·조회 시각·최신성·대체 데이터 여부·출처를 보존한다.
- 예측 혼잡은 개수를 고정하지 않고 각 항목의 예측 대상 시각·혼잡 단계·최소/최대 인구를 보존한다. 예측이 없을 때는 빈 배열과 `forecastStatus: unavailable`을 함께 기록한다.
- 11개 공원을 실제 호출한 결과 모두 정상 정규화됐으며 관측 시각은 조회보다 약 32분 전, 대체 데이터 사용은 모두 `N`, 예측은 공원마다 12개였다. 앞선 표본의 13개와 달라 예측 배열 길이를 계약으로 고정하면 안 됨을 확인했다.
- 스파이크의 45분 최신성 임계값으로는 11곳 모두 `fresh`였지만, 이 값은 운영 정책으로 확정하지 않았다.
- HTTP 오류, API 오류 코드, 빈 응답, 장소 불일치, 필수 필드 누락, 시간 초과, 네트워크 오류는 혼잡이 낮은 상태로 대체하지 않고 명시적인 `unavailable` 원인으로 변환한다.
- 키와 원본 XML은 로그·fixture·파일에 저장하지 않았다. 테스트 fixture는 필요한 필드만 직접 만든 합성 XML이다.

아직 실제 혼잡을 클릭 가능한 추천 화면이나 추천 점수에 투입하지 않았다. 다음 단계에서 캐시·도착 시각 예측 선택·최신성 임계값을 먼저 확정한 뒤 fake 공급자를 교체한다.

남은 운영 위험으로는 공식 엔드포인트의 HTTPS 미지원과 사후 품질 오류 공지를 자동 수집할 경로가 없다는 점이 있다. 실제 서비스에서는 낮은 혼잡값도 절대 사실이 아닌 추정으로 표시하고, 공급자 장애 공지를 확인해 혼잡 근거를 일시 비활성화할 수 있어야 한다.

## 2. 카카오맵 REST API

### 공식 출처

- 카카오맵 REST API: <https://developers.kakao.com/docs/ko/kakaomap/rest-api>
- 카카오맵 이용 정책: <https://developers.kakao.com/docs/ko/kakaomap/common>
- 무료 쿼터 및 추가 사용 요금: <https://developers.kakao.com/docs/ko/getting-started/quota>

### 확인된 범위

- 키워드 장소 검색, 주소→좌표 변환, 대중교통·도보·자전거 경로 조회를 제공한다.
- 대중교통 경로는 출발·도착 좌표를 받아 총 소요시간(초), 거리, 환승 수, 요금, 단계와 카카오맵 길찾기 연결 URL을 반환한다.
- 공개된 대중교통 경로 요청에는 출발 또는 도착 희망 시각 파라미터가 없다.
- 대중교통 경로 무료 쿼터는 1,000회/일, 장소 검색과 주소→좌표 변환은 각각 100,000회/일로 안내된다.
- 2026-07-21부터 개발자 계정에서 카카오맵 API를 처음 활성화한 앱 한 개만 무료 쿼터를 받는다.
- 무료 쿼터를 넘기거나 두 번째 활성화 앱부터는 비즈월렛과 유료 API 설정이 필요하다.
- 추가 대중교통 경로 조회 단가는 현재 공식 문서상 10원/회다. 요금은 변경될 수 있다.

### 호출량 추정

공원별 만남 지점 하나에 대해 모든 참여자 경로를 계산하면 다음과 같다.

| 참여자 수 | 11개 공원 전체 평가 | 무료 1,000회로 가능한 완전 계산/일 |
|---:|---:|---:|
| 2명 | 22회 | 45회 |
| 3명 | 33회 | 30회 |
| 4명 | 44회 | 22회 |
| 6명 | 66회 | 15회 |

장소 검색, 재시도, 대안 만남 지점 계산은 위 수치에 포함하지 않았다. 동일 출발지·도착지 경로를 안전하게 캐시할 수 있는지는 약관 검토가 더 필요하므로 호출량 절감으로 확정하지 않는다.

무료 한도 초과 후 현재 공시 단가를 단순 적용하면 경로 호출 비용만 2명 약속 약 220원, 3명 약속 약 330원, 4명 약속 약 440원이다. 이는 캐시·재시도·복수 만남 지점을 제외한 하한이며, 실제 과금 사용은 별도 승인 대상이다.

### MVP 사용 제안

- 실제 응답 품질이 통과하면 출발지 검색과 대중교통 경로의 1순위로 사용한다.
- REST API 키는 Express 서버에서만 사용한다.
- 무료 단계에서는 한 계정의 첫 번째 카카오맵 활성화 앱인지 확인한다.
- 먼저 11개 전체 후보를 계산해 추천 품질의 기준선을 만든 뒤, 비용 절감용 후보 사전 필터가 추천 결과를 바꾸지 않는지 회귀 테스트한다.
- 경로 결과는 “입력한 미래 시각의 정확한 시간표 기반”이라고 표현하지 않는다.

### 미검증

- 한강공원 만남 지점을 도착 좌표로 사용했을 때 첫/마지막 도보 구간 품질
- 역·학교·건물 등 출발지 검색의 중복 후보 품질
- 심야·첫차·막차와 주말 경로 품질
- 응답 캐시·파생 점수 저장의 허용 범위
- 실제 키의 무료 쿼터 적용 상태

### 실제 키 표본 검증 — 2026-08-12

- `홍대입구역`, `여의나루역` 키워드 검색이 각각 HTTP 200과 좌표를 반환했다.
- 두 검색 결과 좌표 사이의 대중교통 경로 요청이 HTTP 200, API 상태 `OK`로 응답했다.
- 표본에서 15개 경로가 반환됐고 최단 경로는 약 19분이었다. 이 값은 호출 시점의 표본이며 제품 기준값으로 고정하지 않는다.
- 실제 응답 원문과 좌표는 저장하지 않았고, 검증 요약만 기록했다.
- 무료 쿼터 배지와 통계 화면의 차감 상태는 계정 화면에서 별도로 확인해야 한다.

### 3×3 경로 표본 — 2026-08-12

- 홍대입구역·강남역·노원역에서 난지·여의도·뚝섬 임시 만남 지점까지 총 9개 요청이 모두 성공했다.
- 난지는 평균 62분·최장 85분·범위 45분, 여의도는 평균 33분·최장 48분·범위 26분, 뚝섬은 평균 32분·최장 40분·범위 21분이었다.
- 이 단일 시점 결과는 특정 공원의 우위를 뜻하지 않는다. 평균, 최장 시간, 참여자 간 범위가 서로 다른 신호라는 점만 확인했다.
- 총 도보 거리는 0~391m였지만 응답의 마지막 단계만으로 실제 마지막 보행을 입증하지 못했다. 마지막 도보 구간은 검증 전까지 `null`로 취급한다.
- 장소·경로 좌표와 원본 응답은 저장하지 않았다. 경로 결과의 지속 저장·캐시 허용 범위도 아직 확정하지 않았다.

### 5×11 공평성 경로 표본 — 2026-08-12

- 대표 출발지 3명 조합 5개와 11개 공원 임시 만남 지점을 전부 연결한 165개 대중교통 경로 요청이 모두 성공했다.
- 네 조합은 평균 중심·균형 중심·최장시간 중심 정책의 1순위가 같았고, 한 조합은 평균 중심과 나머지 정책의 결과가 달랐다.
- 실험은 이동 공평성만 비교했다. 혼잡·날씨·시설을 실제 상태로 결합한 종합 추천 검증이 아니다.
- 좌표와 원본 경로는 저장하지 않았고, 문서에는 집계된 이동시간과 정책별 공원 선택만 기록했다.

## 7. 정확한 만남 지점 카탈로그

현재 공식 데이터에서 11개 공원의 “피크닉용 대표 만남 지점”을 바로 사용할 수 있는 기계 판독 목록은 확인하지 못했다. 공식 공원 페이지의 안내센터·랜드마크와 카카오 POI를 교차 확인해 11개 임시 후보를 만들었으며 세부 결과는 [`MEETING_POINTS.md`](./MEETING_POINTS.md)에 기록했다.

### 제안 방식

1. 공원별 1~3개 후보를 선정한다: 지하철 출구, 나들목, 안내센터, 눈에 띄는 공식 시설.
2. 공식 미래한강본부 페이지의 명칭·주소와 지도 POI의 좌표를 교차 확인한다.
3. 대중교통 경로의 마지막 도보 구간과 피크닉 구역까지의 접근성을 확인한다.
4. 현장에서 식별할 수 있는 문구와 사진 없이도 설명 가능한 랜드마크인지 검수한다.
5. `sourceUrl`, `verifiedAt`, `verificationMethod`, `status`를 함께 저장한다.

미래한강본부 개별 페이지는 공공누리 제4유형(출처표시·변경금지·비상업적 이용)으로 표시되는 경우가 있으므로, 상업 가능성이 있는 서비스의 재사용 범위는 별도 확인한다. 주소·시설 사실을 검증하는 출처와 콘텐츠를 재배포하는 행위를 구분한다.

현재 카탈로그는 모두 `provisional`이다. POI명·공식 주소 일치 6곳, POI명 일치·주소 불일치 3곳, 공식 주소 좌표만 확인 2곳이다. 공급자 수준에서 좌표를 얻었다는 사실과 현장 만남 지점 검증을 구분한다.

## 8. 실패·최신성·비용 적용 규칙

- 상황 데이터는 `observedAt`/`forecastFor`를 기준으로 `fresh`, `stale`, `unavailable`을 계산한다. `fetchedAt`만으로 최신이라고 판정하지 않는다.
- 최신성 임계값은 여러 시간대의 반복 관측 전까지 확정하지 않는다. 현재 확인한 약 28~32분 인구 지연을 정상 기준으로 굳히지 않는다.
- 행사 0개, 필드 누락, 공급자 오류를 서로 다른 상태로 보존한다.
- 경로가 일부 참여자에게만 성공하면 누락값을 0분이나 평균값으로 채우지 않는다. 정상 공평성 점수는 만들지 않는다.
- 지도 POI 이름·주소 불일치와 주소 좌표 대체는 주의 상태로 남기고, 현장 검수 전 확정 후보로 승격하지 않는다.
- 3명×11개 공원은 기본 33회다. 무료 쿼터 안에서도 불필요한 재시도를 막고 호출 수를 기록한다.
- 유료 API·추가 쿼터는 자동 활성화하지 않는다. 비용 발생 전 사용자 승인을 받는다.
- 시간 초과, HTTP 429, 빈 응답과 오래된 응답은 어댑터 계약 테스트에 포함한다. 실제 공급자 장애 유발 호출은 하지 않고 fixture/fake로 기본 검증한다.

## 9. 현재 데이터 계약 초안

```ts
type Freshness = "fresh" | "stale" | "unavailable";

interface SourceStamp {
  source: string;
  fetchedAt: string;
  observedAt?: string;
  forecastFor?: string;
  freshness: Freshness;
}

interface ParkCondition {
  parkId: string;
  crowd?: {
    level: "relaxed" | "normal" | "busy" | "very_busy";
    predicted: boolean;
    stamp: SourceStamp;
  };
  weather?: {
    precipitationProbability?: number;
    windSpeedMps?: number;
    alert?: string;
    stamp: SourceStamp;
  };
  events: Array<{
    title: string;
    startsAt?: string;
    endsAt?: string;
    stamp: SourceStamp;
  }>;
  controls: Array<{
    summary: string;
    severity: "info" | "avoid" | "closed";
    stamp: SourceStamp;
  }>;
}
```

필드명은 실제 응답 fixture를 얻은 뒤 확정한다.
