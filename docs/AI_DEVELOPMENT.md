# AI 보조 개발 방식

Hangang Compass는 OpenAI Codex를 활용해 구현하는 하네스 기반 AI 보조 개발 프로젝트다. AI 사용 사실을 숨기거나 사람의 기여로 가장하지 않고, 제품 결정과 구현 책임의 경계를 공개적으로 기록한다.

## 역할

### 저장소 소유자

- 해결할 문제, 목표 사용자, MVP 범위를 결정한다.
- 비용, 개인정보, 추천 기준처럼 영향이 큰 선택을 검수한다.
- 코드 대신 실행 가능한 화면과 시나리오 기반 인수 기준으로 결과를 확인한다.
- 배포 여부와 최종 제품 책임을 가진다.

### Codex

- 검수된 요구사항을 작은 작업 단위로 설계하고 구현한다.
- 자동 테스트, 정적 분석, 빌드 및 실행 검증을 수행한다.
- 제품 문서와 구현이 어긋나지 않도록 함께 갱신한다.
- 외부 데이터의 제약과 실패 상태를 확인하고, 확인하지 못한 사실을 추측하지 않는다.
- 중요한 제품 선택이나 비용·개인정보 범위의 변경은 임의로 확정하지 않고 검수 자료를 제시한다.

구체적인 저장소 작업 규칙은 [`AGENTS.md`](../AGENTS.md)를 따른다.

## 하네스

Codex의 결과를 대화의 신뢰에만 의존하지 않고 다음 장치로 검증한다.

- `PRODUCT.md`: 제품 목표와 범위
- `docs/ACCEPTANCE.md`: 사용자가 코드 없이 확인할 시나리오
- `docs/ARCHITECTURE.md`: 시스템 경계와 기술 선택
- `tasks/ROADMAP.md`: 위험 우선 구현 순서
- 자동 테스트와 고정 fixture: 추천 결과와 설명의 재현성
- CI: 테스트, 정적 분석, 빌드 실패의 자동 차단

CI는 애플리케이션 골격과 함께 구성하며, 구성 전까지는 실행한 로컬 검증과 실행하지 못한 항목을 작업 결과에 명시한다.

## 저작 및 기여 표기

- Git 커밋은 저장소를 소유하고 결과를 승인하는 실제 GitHub 계정으로 기록한다.
- Codex를 실제 GitHub 계정인 것처럼 보이게 하는 가짜 이메일이나 `Co-authored-by` 표기는 사용하지 않는다.
- AI 보조 사실은 이 문서와 README에서 공개한다.
- 필요할 경우 커밋 메시지에 `Assisted-by: OpenAI Codex` 트레일러를 사용할 수 있다. 이 표기는 작업 방식의 기록이며 GitHub 공동 작성자 표기가 아니다.
- 사람 또는 도구의 기여 범위가 달라지면 당시 사실에 맞게 문서를 갱신한다.

## 제품 안에서의 AI 범위

Codex는 개발 도구로 사용하지만, MVP 추천 엔진의 필수 실행 경로에는 생성형 AI를 넣지 않는다. 공원 추천과 설명은 같은 입력에서 같은 결과가 나오는 규칙과 점수로 생성하며, 데이터 출처·조회 시각·신뢰 상태를 함께 보존한다.

## 완료 기준

AI가 코드를 생성했다는 사실만으로 작업이 완료되지는 않는다. 요청된 동작, 관련 자동 검증, 실패 상태, 문서 갱신, 개인정보와 비밀키 점검, 사용자의 검수 방법이 모두 준비돼야 완료로 판단한다.
